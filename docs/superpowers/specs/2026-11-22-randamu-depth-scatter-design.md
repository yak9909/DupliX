# randamu 設計書: 深度テスト付きランダム配置エフェクト（After Effects 2025）

- 日付: 2026-11-22
- 状態: 下書き（実験 S1〜S4 の結果待ちの項目あり。「未確定」と書いた所）。2026-11-23: 絶対条件（第 2 節）と、他レイヤーの画素を AEGP の描画で取る方針（4.2 節）を追記
- 対象: After Effects 2025（25.6）/ Windows x64 / AE SDK 25.6（`C:\AfterEffectsSDK\ae25.6_61.64bit.AfterEffectsSDK`）

## 1. 目的と背景

エフェクトを適用したレイヤーの画像を、3D 空間（XYZ）にランダムに n 個配置する。
普通のランダム配置プラグインと違うのは、**コンプ内の他のレイヤーとの前後関係を画素単位で判定する（深度テスト）** こと。
コピーが他レイヤーより奥にある部分は隠れ、手前にある部分は見える。

AE 標準の 3D はレイヤー単位でしか前後を並べ替えないため、1 枚のレイヤーの出力を他レイヤーの「手前」と「奥」に同時に置くことはできない。これをエフェクト内部の深度計算で実現する。

## 2. ゴール・非ゴール・アンチゴール

### 絶対条件（利用者が 2026-11-23 に確定。変更・妥協しない）
1. **ランダム配置をするレイヤーに、エフェクトを 1 つ掛けるだけで成立する。** 補助レイヤー、プリコンプ、複製レイヤー、他レイヤーの非表示、効果プリセットからの適用、手作業の設定などを利用者に求めない。メニューから普通に適用しただけで正しく動くこと。
2. **他レイヤーによる隠れは、必ず AE のレンダリング結果をもとに判定する。** 他レイヤーのマスク・エフェクト・トラックマットは、隠す判定に必ず反映させる（AE が実際に描く形で隠す）。素材の元の形（「ソース」）で代用しない。

### ゴール
- **1 レイヤーに 1 エフェクトで完結する**（絶対条件 1）。
- コピーの数 n に上限を設けない（性能の許す限り）。
- コンプ内の**すべてのレイヤー**が深度テストの対象（利用者が対象を選ぶ必要がない）。
- 他レイヤーを動かす・変えると、正しく再描画される（古いキャッシュが残らない）。
- マルチフレームレンダリング（MFR）と `aerender` で正しく動く。

### 非ゴール（今回はやらない）
- 対象レイヤー数の上限なし（**将来対応する**。第 8 節）。最初の版はスロット数（例: 64）が上限。
- GPU 描画。最初は CPU のみ。
- Advanced 3D / Cinema 4D レンダラーとの厳密な一致。最初はクラシック 3D を基準にする。
- ライト・影・モーションブラー・被写界深度をコピーに反映すること（後で検討）。

### アンチゴール（動いても失敗とみなすもの）
- 他レイヤーが変わったのに古い絵が出る（キャッシュ不整合）。
- 利用者に「他レイヤーを隠す」「エフェクトレイヤーを複製する」などの運用を強いる。
- AE が不安定になる（描画中の再入による無限ループ・デッドロック・クラッシュ）。

## 3. 制約（調査で分かったこと）

- エフェクトの出力は 2D の RGBA だけで、Z は持てない。AE 内部の深度は Artisan（3D レンダラー）の中にしかない。
- 描画中に `AEGP_RenderAndCheckoutLayerFrame` で他レイヤーを取ると、無限ループになりうると公式ガイドが警告している（描画目的での使用は非推奨）。
- エフェクトが AEGP で外部の情報を読むと、AE はその依存を知らず、キャッシュが更新されない。ただし SDK サンプル `SmartyPants` は、PreRender で AEGP の値を読んで `GuidMixInPtr` に混ぜる方法を示している（将来の上限なし対応の足がかり）。
- `PF_Param_LAYER` のチェックアウトは公式の仕組みなので、依存の追跡・MFR・`aerender` が正しく動く。ただし、チェックアウトした画素にはレイヤーの変換（位置・回転・カメラ）が入っていない。
- エクスプレッションは AE が依存を追跡するので、エクスプレッション付きのパラメータ経由で他レイヤーの位置を読めば、キャッシュが正しく更新されるはず（実験で確認する）。
- `AEGP_GetEffectCamera` は描画中に動かないという報告がある。

## 4. 検討した方式と選んだもの

### 4.1 合成の方式

| 方式 | 内容 | 得るもの | 失うもの |
|---|---|---|---|
| A: 全体の自前合成 | 全レイヤーを自前で深度合成し、シーン全体を 1 枚に出力 | 交差も含めて正確 | 重い。ブレンドモード・ライト・調整レイヤーの再現が必要。元レイヤーを隠す運用が要る |
| B: 前後 2 枚の出力 | レイヤーを複製し「手前用」「奥用」を出力 | 軽い | 複数レイヤーの間への挟み込みが正しくない。1 レイヤー 1 エフェクトに反する |
| C: Z 範囲ごとの多枚出力 | 区間ごとに別レイヤーを出力 | AE 標準の合成を保てる | 区間の境でコピーが切れる。レイヤー数が増える。1 レイヤー 1 エフェクトに反する |
| **A': くり抜き方式（採用）** | エフェクトレイヤーを最上段に置き、コピーだけを出力。他レイヤーより奥の部分はアルファを削る | 他レイヤーを隠す必要がない。ブレンドモード等の再現が不要（シーンは AE 本体が描く）。1 レイヤー 1 エフェクトで完結 | 半透明の手前レイヤー越しの画素だけ近似になる（4.3） |

利用者は「エフェクト内部で深度バッファを持ち、自前で合成する」「1 レイヤー 1 エフェクトで完結」を選んだ。A' はこの条件を満たし、A より安全で軽いので採用する。Trapcode Particular の Obscuration Layer と同系統の考え方だが、対象を全レイヤーに広げ、アルファを読むので縁と半透明も扱える。

### 4.2 他レイヤーの情報の取り方

| 方式 | 得るもの | 失うもの |
|---|---|---|
| **隠しレイヤーパラメータ ＋ エクスプレッション（採用）** | 公式の仕組みなので、キャッシュ・MFR・aerender が正しく動く | スロット数に上限ができる（例: 64） |
| 描画中に AEGP で直接取る（黒魔術） | 上限なし | キャッシュ不整合と再入の危険を自前で抑える必要がある |

利用者は上限を許容した（将来は上限なしにする）。

**2026-11-23 の変更（実験 S2b の結果を受けて）**
- 実験 S2b で、`PF_Param_LAYER` の既定の取り込み方（「ソース」とみられる）では、対象のマスク・エフェクト・トラックマットがチェックアウトに含まれないと分かった（`docs/experiments/2026-11-22-spike-log.md` 7.1 節）。「エフェクトとマスク」への切り替えは SDK にもスクリプトにもなく、効果プリセット経由しかない。これは絶対条件 1・2 に反する。
- 利用者は **AEGP でレイヤーを描画させる方式**（案 3）を選んだ。他レイヤーの画素は `AEGP_RenderAndCheckoutLayerFrame`（`AEGP_LayerRenderOptions`。ヘッダの記述では既定で全エフェクトを描画）など、AE 自身の描画結果から取る。
- 未確認で、実験で確かめること:
  - マスクとトラックマットが含まれるか。含まれない場合に、AE の描画結果から得る別の手段（例: コンプ単位の描画 `AEGP_RenderAndCheckoutFrame` や、対象ごとの描画の組み合わせ）。
  - 描画中に呼んだときの再入・無限ループ・デッドロック（第 3 節の警告）。MFR と `aerender` での動作。
  - キャッシュ: AE が依存を知らないので、対象の変更を `GuidMixInPtr` に混ぜる仕組み（`SmartyPants` の方法）が必要。何を混ぜれば変更を漏れなく拾えるか。
  - テキスト・シェイプ・コラップスしたレイヤーの座標系（S2b ではコンプ座標で返った）。
- スロット（`PF_Param_LAYER`）＋エクスプレッションは、位置と深度の取得（`toComp` など）と依存の追跡には引き続き使える可能性がある。画素の取得だけを AEGP に替えるか、全体を AEGP にするかは実験で決める。

**2026-11-23 実験 S5 の結果**（詳細は実験記録 7.2 節）
- 描画中（PreRender・SmartRender）に `AEGP_RenderAndCheckoutLayerFrame` を呼べる。MFR オン／オフ・aerender で、デッドロックもクラッシュもなかった。
- 受け取りの GUID を `GuidMixInPtr` に混ぜると、対象ごとに別のキャッシュになる（他レイヤーの変更で再描画されるかは S4 で確かめる）。
- 反映されるもの: マスク、エフェクト（レイヤーの範囲の中だけ）。テキスト・シェイプはコンプ座標の投影済みの絵で返る（そのまま使える）。
- 反映されないもの（絶対条件 2 に関わる。利用者と相談する）:
  1. トラックマット。
  2. レイヤーの本来の範囲からはみ出すエフェクトの結果（ずらす、ドロップシャドウ、グローなど）。`AEGP_LayerRenderOptionsSuite2` には ROI を広げる関数がない。
  3. コラップスしたプリコンプ（AEGP では画素が返らない）。スロットのチェックアウトならコンプ座標の絵が取れて形は一致するが、そのレイヤー自身のマスク・エフェクトは入らない見込み。
- トラックマットの対処の候補: `AEGP_LayerSuite9::AEGP_GetTrackMatteLayer` でマットのレイヤーを取り、それも AEGP で描画し、マットの種類（`AEGP_LayerTransferMode.track_matte`: アルファ／反転アルファ／ルミナンス／反転ルミナンス）に従ってコンプ座標で掛け合わせる。素材はどちらも AE の描画結果で、掛け合わせだけを自前で行う。
- キャッシュ: 受け取りの GUID は対象の中身の変化だけを拾う見込み。対象の移動・カメラの変化は、エクスプレッション付きのパラメータ（角の位置）が拾っている。

**2026-11-23 実験 S5c の結果**（詳細は実験記録 7.3 節）
- はみ出すエフェクト: `AEGP_NewFromLayer` のあとで、`BEE.dll` が公開している AE 内部の `BEE_RenderOptions::SetROI` を呼んで範囲を広げると、エフェクトの結果の全体が返る（t_effect 合格）。非公開の関数に頼る「黒魔術」で、見つからないときは既定の範囲に戻す。
- コラップスしたプリコンプ: 範囲を大きく（±約 3 万 px）広げると、AEGP でコンプ座標の投影済みの絵が返る（合格）。スロットのチェックアウトに頼る必要がなくなり、そのレイヤー自身のマスク・エフェクトも入る見込み（未確認）。
- 残る問題はトラックマット（案 A で実験する）。
- 本番で指定する範囲の決め方（上限）は未決（実験記録 7.3 節の注意）。

### 4.3 くり抜きの式

画素ごとに、コピーより手前にある他レイヤーの重なり（不透明度の合成）を `Na`、そのプリマルチ色を `Nrgb`、コピーの色を `C`（プリマルチ、アルファ `c`）とする。

- **既定（くり抜きのみ）**: 出力 = `C × (1 − Na)`。手前レイヤーの色は使わない。誤差は手前レイヤーのアルファ `a` について `a(1−a)` に比例し、`a` が 0 か 1 なら 0。ライトや非ノーマルのブレンドに強い。
- **補正（オプション）**: 出力アルファ = `c`、出力色 = `c × Nrgb + (1 − Na) × C`（＝ 手前スタックをコピーに重ねたもの）。手前レイヤーがノーマルブレンドで、ライトを受けない場合に正確。ライトで色が変わるレイヤーでは誤る。

既定は「くり抜きのみ」。補正は後で選べるようにする（未確定）。

## 5. 全体構成

```
[エフェクトを適用したレイヤー（最上段・2D）]
   │ 入力: 自分の画像（コピーの元絵）
   │ 隠しパラメータ:
   │   Slot 1..N        … PF_Param_LAYER。コンプの各レイヤーを自動で割り当てる
   │   Slot k の角座標   … POINT_3D ＋ エクスプレッション（画面位置と深度）
   │   自レイヤーの変換   … POINT_3D ＋ エクスプレッション（toComp）
   │   コンプサイズ・カメラ … エクスプレッション
   ▼
 PreRender
   ・出力範囲をコンプ全体に広げる（自レイヤーの変換を打ち消す）
   ・各スロットのレイヤーをチェックアウト予約
 SmartRender
   ・コアライブラリに渡す: コピーの元絵、配置パラメータ、各レイヤーの画素と平面
   ・コアが深度テストとくり抜きをして、コンプ座標の画像を返す
   ▼
 AE が通常どおり「最上段のレイヤー」として下のシーンに重ねる
```

### 5.1 コアライブラリ（AE に依存しない C++）
- 乱数配置（シード固定で再現可能）、投影、ラスタライズ、深度バッファ、くり抜き合成。
- AE のヘッダに依存しない。単体テストを数ミリ秒で回せる。

### 5.2 AE ラッパー（薄く保つ）
- パラメータ定義、スロットの自動割り当て、チェックアウト、座標系の変換、ピクセル形式（8/16/32bpc）の変換。

### 5.3 各レイヤーの深度の求め方
- 3D レイヤーは平面とみなす。3 つの角の画面位置と深度（エクスプレッションで取得）から、画面上の各画素の深度を補間する（透視補正のため 1/z を線形補間）。
- 画面位置は `toComp()` で AE 自身に計算させる。ズーム・ピクセル縦横比・親子・自動方向を自前で再現しないため（未確定: 実験で `toComp` の挙動を確認）。
- 深度はカメラ空間の Z（`activeCamera.fromWorld(L.toWorld(角))[2]`）。

### 5.4 未確定の扱い（実験の後に利用者と決める）
- エフェクトレイヤーより上にあるレイヤー: 深度に関係なくコピーの上に重なる（AE の重ね順のため）。説明書きで「最上段に置く」と案内する案。
- 2D レイヤー: 深度を持たないので「最背面」とみなす案。
- 3D モデルレイヤー・テキストの文字単位 3D・コラップスしたプリコンプなど、平面でないもの: 平面近似か対象外か。
- コピーの向き（常にカメラを向く／ランダム回転）、サイズや回転のばらつき、時間変化などの配置パラメータ。
- 合成の段階で掛かる性質（AEGP のレイヤー描画に入らないもの）: 不透明度・トラックマット・表示状態（目のスイッチ、時間の範囲）・ソロは自前で反映する方式で解決済み（実験記録 7.4〜7.6 節）。ヌル・ガイド・調整レイヤーは対象から外す。**対象より上の調整レイヤー（下のレイヤーの見た目を変える）、描画モード、レイヤースタイルは未確認で、扱いを決める必要がある。**
- **（11/23 夜 決定）くり抜き方式（A'）は不採用**。比較画像で、半透明・ぼかしの後ろで背景が透け、描画モードの後ろでコピーが消えることを利用者が確認し、「絵の改変に等しい」として拒否。正しい見た目（コピーを本物の 3D レイヤーとして置いた参照コンプの AE の描画）と RGB で一致することが必須。新しい方式（コピーがある画素だけを全部合成し直す）は HANDOFF と実験記録を参照。本文は改訂時に書き直す。以下は経緯として残す。
- **くり抜き方式（A'）の原理上の近似**: 手前のレイヤーのアルファが 0 か 1 のところでは正確だが、半透明のところでは近似になる。例: 不透明度 50% のレイヤー X がコピーの手前にあるとき、正しい見た目は「コピー×0.5＋X×0.5」だが、A' では「コピー×0.5＋X×0.25＋背景×0.25」になる。半透明・アンチエイリアスの縁・描画モードは、データの取り方ではなく方式そのものの理由で近似になる（不透明度の対処は 0 と 1 でしか確かめていない）。これを許容するかを利用者が決める。
- このエフェクトを持つ別のレイヤー同士の前後関係: 今は互いに対象から外す（再入の防止のため）。どう重なるべきかは利用者が決める。
- 位置と深度の取得: **（11/23 決定）スロット＋エクスプレッションをやめ、すべて AEGP で取る**（S5b で全項目合格。速く、スロット数の上限もなくなる）。本文の 4 節の該当箇所は、設計書の改訂時に書き直す。

## 7. 検証方法（自動化）

1. **コアの単体テスト**: 投影・ラスタライズ・深度テスト・くり抜きを AE なしでテストする。
2. **AE を正解として使う比較テスト**: プラグインがコピーの配置を JSON に書き出し、スクリプトで「本物の 3D レイヤーを同じ位置に複製したコンプ」を作る。クラシック 3D でレンダーした結果と画素単位で比べる。内部の画素は厳しく、縁と半透明の画素は許容幅つきで判定する（4.3 の誤差と AE の補間のため）。テストコンプのレンダラーはスクリプトで明示する。
3. **実行**: シーン生成は `AfterFX.com -noui -r`、レンダーは `aerender`（MFR オン／オフ両方）。プラグインはログ（環境変数で出力先を指定）を書き、私が自動で読んで判定する。
4. **クラッシュ時**: Windows のエラー報告（WER）の LocalDumps でダンプを残し、解析する（デバッガ cdb は未導入。必要になったら Windows SDK の Debugging Tools を入れる）。
5. **ホットリロード**: UI で触りながら調整する段階で、薄いローダー（本体 DLL を毎回別名でコピーして `LoadLibrary` し、呼び出しを転送）を導入する。パラメータ構成やシーケンスデータの構造を変えたときは AE の再起動が必要。

## 8. 将来: 対象レイヤー数の上限なし

- 描画中に AEGP でレイヤーの一覧と状態を読み、`GuidMixInPtr` に混ぜてキャッシュの更新を AE に伝える（SDK サンプル `SmartyPants` と同じ手法）。
- 画素の取得は、描画外（アイドル時など）に取って共有キャッシュに置く方式などを検討する。
- コアライブラリは「レイヤーの画素と平面の一覧」を受け取るだけにしておき、取得方法の差し替えだけで対応できるようにする。
