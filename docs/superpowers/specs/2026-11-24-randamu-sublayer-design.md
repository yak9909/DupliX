# randamu 設計書 v2: サブレイヤー方式のランダム配置エフェクト（After Effects 2025）

- 日付: 2026-11-24
- 状態: **承認済み（2026-11-24）**。第 6 節は決定済み。
- 旧設計書: `2026-11-22-randamu-depth-scatter-design.md`（くり抜き方式 A' の時代。経緯として残す。方式の部分は本書で置き換える）
- 実験の記録: `HANDOFF.md`（試験 1〜23）、`docs/experiments/2026-11-22-spike-log.md`、決定事項 `docs/decisions-2026-11-24.md`
- 対象: After Effects 2025（25.6）/ Windows x64 / AE SDK 25.6 / クラシック 3D レンダラー

## 1. 目的

エフェクトを適用したレイヤーを、3D 空間にランダムに n 個のコピーとして配置する。各コピーは AE 自身の 3D 描画で「本物の 3D レイヤー」として描かれる。そのため、コンプ内の全レイヤーとの前後・交差、ライトの陰影と影、被写界深度、モーションブラー、上にある調整レイヤーが、同じ位置に本物の複製レイヤーを置いた場合と画素単位で同じになる。

## 2. 絶対条件（利用者が確定。変更・妥協しない）

1. ランダム配置をするレイヤーにエフェクトを 1 つ掛けるだけで成立する。補助レイヤー・プリコンプ・複製レイヤー・効果プリセット・手作業の設定を求めない。
2. 見た目は「各コピーを本物の 3D レイヤー（元レイヤーの複製）として同じ変形で置いたコンプ」を AE が描いた絵と RGB(A) で一致する（8 bpc で ±1/255 程度）。近似は不可。
3. コンプ内の全レイヤーが前後判定の対象（利用者が選ぶ必要がない）。

## 3. 方式（決定: サブレイヤー方式）

AE 内部には、文字単位 3D のテキストのために「1 つのレイヤーが複数の板（サブレイヤー）として 3D 描画される」仕組みがある。`BEE.dll` の `BEE_AVLayer` の仮想関数を差し替えて、このエフェクトを持つレイヤーにだけ「サブレイヤーが n 枚あり、それぞれこの変形・不透明度」と答えさせる。AE はそれを本物の 3D の板として描くので、絶対条件 2・3 は作りから満たされる。

差し替える箇所（実験で確認済み。名前は AE 2025 のもの）:

| 箇所 | 内容 |
|---|---|
| `SubLayersRenderSeparately`（vtable） | 対象レイヤーなら真 |
| `SubLayerRenderCount`（vtable） | キャッシュ付きの問い合わせなら n、キャッシュなしなら元の答え（これでラスターのレイヤーも全体の絵で描かれる） |
| `GetSubLayerRects`（vtable） | 矩形 = 元の矩形、M3 = 単位行列、M4 = コピー i の変形（行ベクトル形式、時刻の関数） |
| `IsLayerType`（vtable） | エフェクトの有無でサブレイヤーを止める判定（命令の並びで見分けた 1 か所）からの呼び出しにだけ、対象レイヤーで偽を返す |
| `BEE_GetArtisanLayerOpacity`（AEGPDriver.aex の取り込み表） | 元の値 × コピー i の不透明度 |

安全策:
- 差し替え先は、公開関数の名前と仮想関数表の照合、命令の並びの照合で実行時に探す。1 つでも見つからなければ何も差し替えない（コピーが出ないだけで、AE は落ちない）。エフェクトの UI にその旨を表示する。
- 差し替えた関数は、対象でないレイヤーでは元の関数をそのまま呼ぶ。対象かどうかの判定は、登録済みのレイヤー ID の一覧との照合だけ（描画スレッドや UI スレッドの中で AEGP を呼ばない。試験 20 で、UI スレッドの中から AEGP を呼ぶと AE が止まった）。
- AE の版が変わったら、差し替え先を調べ直す（第 8 節）。

## 4. 動作の流れ

1. **GLOBAL_SETUP**: 差し替えを入れる（全プロジェクト共通、1 回だけ）。
2. **SEQUENCE_SETUP / RESETUP（読み込み時）/ パラメータ変更など**: 自分のレイヤーを登録一覧に入れる。エフェクトの削除（SEQUENCE_SETDOWN）で外す。レイヤー ID はコンプの複製で重なるおそれがあるので、鍵はコンプとレイヤーの組にするか、照合で当たったときに「そのレイヤーがこのエフェクトを持つか」を確かめる（どちらにするかは第 9 節の確認の結果で決める）。
3. **描画時**: AE が対象レイヤーに問い合わせる → 差し替えた関数が、乱数から n 枚の変形と不透明度を作って返す。パラメータの読み方はスレッドで分ける。
   - 描画スレッド（aerender・レンダーキュー・MFR）: そのレイヤーのこのエフェクトのパラメータを AEGP で読む（問い合わせの時刻で。試験 15 で確認済み）。
   - メインスレッド（UI。GLOBAL_SETUP で控えたスレッド ID で見分ける）: **AEGP を呼ばない**（試験 20 で、UI スレッドの BEE の関数の中から AEGP を呼ぶと AE が止まった）。エフェクト自身のコマンドの中で最後に読んだパラメータの写しを使う。
   - プレビューの問い合わせがどのスレッドから来るかは未確認（第 9 節の最初の項目）。
4. **エフェクト自身の描画（SmartRender）**: 入力をそのまま出力する（コピーの絵の元になる）。
5. **キャッシュ**: 配置はエフェクトのパラメータだけから決まるので、パラメータを変えれば AE が描き直す（試験 14）。

## 5. パラメータ（案。決定 5 による）

| パラメータ | 種類 | 内容 |
|---|---|---|
| コピー数 | 整数（0〜上限なし。スライダーの目安 1〜1000） | 多いと重くなる（2500 枚で 1 フレーム約 20 秒）ことを説明に書く（決定 4） |
| 乱数の種 | 整数 | 同じ種なら同じ配置 |
| 位置の範囲 X / Y / Z | 数値 ×3 | レイヤーの座標で、アンカーポイントを中心に ±範囲で一様に散らす（決定 3） |
| 回転の範囲 X / Y / Z | 角度 ×3 | アンカーポイントを中心に ±範囲で一様に回す（決定 2） |
| 拡大縮小の範囲 | 最小 % / 最大 % | 縦横同じ比率で一様に |
| 不透明度の範囲 | 最小 % / 最大 % | 一様に。レイヤー自身の不透明度に掛ける |
| 1 枚目は元の位置 | チェック（既定オフ） | オンなら 1 枚目のコピーは元の位置・向き・大きさ・不透明度のまま（第 6 節の 1） |

- 各量は種とコピー番号だけから決まる乱数で作る（コピー数を増やしても既存のコピーは動かない）。
- パラメータはキーフレームで動かせる（描画時刻で読むので、モーションブラーも正しく付く。試験 13）。
- 時間のずらし（コピーごとに再生位置を変える）は最初の版に入れない（将来）。
- **実験で正解との一致を確かめたのは、平行移動・矩形の中心を軸にした回転・不透明度だけ**。拡大縮小、中心からずらしたアンカー、対象レイヤー自身に回転・拡大縮小・親があるとき、コピー数 0・1 は未確認（第 9 節）。特に拡大縮小は、コピーの絵が等倍で 1 回だけ作られて引き伸ばされる場合、本物の 200% のレイヤーと絵が変わりうる。

## 6. 利用者の決定（11/24）

- 1 → **(a) コピーだけ＋「1 枚目は元の位置」のチェック**。
- 2 → **(b) 3D でないときはコピーを出さず、エフェクトの UI に「3D にしてください」と案内する**（2D のままで描けることが確かめられた場合も、まずは案内の形で始める。描けるなら利用者に相談して変えてよい）。

以下は質問したときの文面。

1. **元のレイヤー自身の扱い**: 今の仕組みでは、レイヤーは n 枚のコピーに置き換わる（元の位置の 1 枚は残らない）。(a) コピーだけ（おすすめ。元も残したいときはコピー数に含めて「1 枚目は元の位置」を選べるチェックを付ける）、(b) 常に元＋n 枚。
2. **2D レイヤーに掛けたとき**: 実験はすべて 3D レイヤーで行った。AE 本来の判定では 3D でないと別々に描かれないが、その判定は差し替えているので、2D のままでも描けるかは未確認。描けない場合の扱いを先に決めておきたい。(a) エフェクトを掛けたときに 3D スイッチを自動で入れる（取り消し可能、おすすめ）、(b) 3D でないときは何もせず、エフェクトの UI に「3D にしてください」と出す。(a) は絶対条件 1 に沿う。

## 7. 構成

- **コア（AE に依存しない C++）**: 乱数（種とコピー番号から決まる）、パラメータからコピー i の M4 と不透明度を作る計算。単体テストを AE なしで回す。
- **差し替え層**: 差し替え先の探索、差し替えた関数、登録一覧（読み取りが速く、MFR の同時呼び出しで安全なもの）。
- **エフェクト本体**: パラメータ定義、ID の登録と解除、そのまま出力。
- 実験コード（`spike/`）は流用しない。分かった事実と手順だけを使って書き直す。

## 8. 検証（自動）

- 既存の正解比較（本物の複製レイヤーで作った参照コンプと画素比較、aerender の MFR オフ・オン）を製品のプラグインで通す。シーン: 床・交差する壁・ライトと影・カメラ、被写界深度・調整レイヤー・モーションブラー、PNG 素材、エフェクト付き、複数レイヤー、コピー 100 枚。
- 参照コンプはスクリプトで作る。乱数はコアと同じものをスクリプトにも実装するか、プラグインが配置を書き出す。
- 保存して開き直したプロジェクトでも同じ結果になること。
- 差し替え先が見つからない場合（わざと探索を失敗させる）に、AE が落ちず、コピーが出ないだけになること。

## 9. まだ確かめていないこと（実装の中で確かめる。利用者に渡す前に上の 4 つは必ず済ませる）

- **UI のプレビューで、スクラブとパラメータ変更をしても AE が止まらないこと**。問い合わせがどのスレッドから来るか。
- **拡大縮小と、中心からずらしたアンカーでの回転が正解と一致すること**。
- **保存したプロジェクトを開いたとき・aerender で、最初の描画の問い合わせより前にエフェクトが自分を登録できること**（実験では環境変数で ID を渡していた）。
- **コンプを複製して同じレイヤー ID ができたときに、エフェクトのないレイヤーにコピーが出ないこと**。
- 対象レイヤー自身に回転・拡大縮小・親があるとき（散らばりがレイヤーと一緒に動く）。
- 2D レイヤーのままで描けるか。コピー数 0・1 のときの見え方。
- エフェクトを無効（fx スイッチ）にしたとき・エフェクトを削除したときに、コピーが消えること。
- 3D スイッチの自動切り替え（第 6 節の 2 で (a) を選んだ場合）がエフェクトのコマンドの中からできるか。
- 同じ枚数の本物のレイヤーとの速度の比較。

### 12.2 速さ

4. **GPU に対応させる。** エフェクト自身の描画（入力をそのまま出す）は GPU（`PF_OutFlag2_SUPPORTS_GPU_RENDER_F32`、SmartRender の GPU 版）でも動くようにし、GPU の描画の流れで CPU に戻されないようにする。コピーの 3D 描画はクラシック 3D レンダラー（CPU）が行うので、そこを GPU に移せるかは調査の対象（無理なら理由を書く）。
5. **CPU と GPU の両方で、さまざまな高速化を行う。** 候補: フレームごとのパラメータ読み取りと変形の計算の使い回し（同じ時刻の 3 回の PreRender・`GetSubLayerRects` の問い合わせで再計算しない）、登録一覧の読み取りの軽量化、コピーの絵（ラスター）を 1 回だけ作って全コピーで共有、SIMD・並列化。
6. **CG の複製物（インスタンス）の扱いの定番の最適化と技術資料を読み、その手段を取り入れる。各手段はパラメータでオン／オフ・強さを設定できるようにする。** 調べる候補: 視錐台カリング（画面外のコピーを描かない）、遮蔽カリング（Hi-Z など）、距離によるカリング、LOD（遠いコピーの絵の解像度を下げる）、インポスター、空間の分割（BVH・グリッド）による範囲の計算、描く枚数の上限（予算）、前後の並べ替えの省略。資料（GPU Gems、Real-Time Rendering などの定番、ゲームエンジンのインスタンス描画の資料）は原文で読み、出典を記録する。
7. **高速化はパラメータで選べるので、一部の高速化を有効にしたときに絶対条件（第 2 節の 2 の画素一致、12.4 の交差など）が満たされなくなることは許容する。** （案、着手時に利用者に確認）既定値では、正確さを崩す高速化をオフにして絶対条件を満たす。正確さを崩す設定には、パラメータの説明でそのことを示す。

### 12.3 確かめること（挙動の保証）

8. **コピーが画面の外に完全に出たとき**の挙動（描かれない・落ちない・遅くならない）。ただし画面外のコピーでも、影・反射のように画面内の絵に効くものがある（ライトの影、モーションブラーで画面に入る、被写界深度）。視錐台カリングはこれを崩しうる → 12.5 の判定で対処する。
9. **コピーにエフェクトを掛けた場合**（対象レイヤーにエフェクトがある場合。試験 9・`png_fx` で基本は確認済み）の挙動を、範囲が広がるエフェクト（ぼかし・グロー・ドロップシャドウ）でも確かめる。
10. **画面外にはみ出ているコピーにエフェクトが掛かっているとき、全体が映っているときと絵が変わらないことを保証する**（PreRender で、AE がコピーの見えている部分だけを要求してきても、レイヤー全体の範囲を要求・出力する。コピーの絵は 1 つを全コピーで共有しているので、ある 1 枚の見え方で範囲を削ると、ほかのコピーの絵も変わる）。正解比較のケースを足して確かめる。

### 12.6 深度テスト後のコピー全体に、1 枚の絵としてエフェクトを掛ける（11/24 利用者の要望）

今の仕組みでは、レイヤーのエフェクトはコピーに分かれる前の元の 1 枚に掛かる（各コピーが同じ結果を持つ。手で複製した場合と同じ）。利用者は、深度テストで見えている部分だけになったコピー全体を 1 枚の絵として扱い、それにエフェクトを掛けたい。

- 手順: (1) AE の 3D 描画のあと、コピーのうち見えている部分の絵とマスクを取り出す → (2) その絵にエフェクトを掛ける → (3) 画面に重ねる（コンポジットのレンダーパスと同じ考え方）。
- **利用者の決定（11/24）: 見た目は (a)「エフェクトの結果は手前のレイヤーの上にもにじむ」で進める。将来は (b)「エフェクトの結果も深度テストにかけて、手前のレイヤーの後ろに隠す」に切り替えられるようにしたい。**
- 進め方（利用者が承認）: まず、AE の 3D 描画が終わった直後に処理を差し込める場所が AE の内部にあるかを短い試験で調べる。結果を見て、続けるか、補助のレイヤー（調整レイヤー＋トラックマット）を使う方法にするかを利用者と相談する（後者は絶対条件 1 に反するので、利用者の判断が要る）。
- 決めること: エフェクトを掛けたあとの絵を、重なり順のどこに置くか（最前面か、元のレイヤーの位置か）。
- 着手の条件: 今のプラグインを利用者がテストしてから。

### 12.8 対象のレンダラーはクラシック 3D のみ（11/24 利用者の決定）

- **Advanced 3D は映像制作で不都合な場面が多いので、軽量化はクラシック 3D の中で実現する。**
- Advanced 3D（内部名 Calder）のコンプでサブレイヤーを答えると AE が落ちた（`tests/ae/renderers.jsx`）。→ フックは `BEE_CompItem::ArtisanIsCalder`／`ArtisanIsErnst` が真のコンプでは対象にせず、元のレイヤーをそのまま描く（修正済み。クラシック 3D の内部名は Escher）。
- 書き出しの計測（`run_perf.ps1`、aerender の「合計経過時間」＝起動を除く）: 60 フレームで、コピーなし 10 秒、DupliX 400 枚（回転なし）13 秒、本物のレイヤー 400 枚（回転あり）30 秒。書き出しではコピーの描画は大きな負担になっていない。利用者が重いと感じた場面（プレビューか、枚数、影）をそろえて測ってから、12.5・12.7 や GPU での描画の差し替えを検討する。

### 12.12 2 つの方式の区別（11/24 利用者の確認）

- **まとめる最適化**（12.7 の (3)）: 描画結果が変わらない範囲で、まとめられるコピーだけを 1 枚の絵にする。ほかのレイヤーとの前後・交差は正確なまま。ライト・影・被写界深度・モーションブラーが効くコピーはまとめない。**利用者の決定: 群れの中の描き方は AE と同じ計算を再現せず、縁などの 1〜2 段階の差は許す（パラメータの説明に書く）**。
- **高速モード**（12.7 の (4)、12.11）: 最初から全部を 1 枚の絵として出す。普通の複製プラグインと同じ。
- 順番: 高速モードを先に作り、まとめる最適化はその描画の部品を使って作る。

### 12.11 高速モードの設計（11/24。利用者の承認済み）

**利用者の決定（11/24）**
- 1 枚の面の奥行きは、レイヤーのアンカーの奥行き（ほかの 3D レイヤーとの前後はこの奥行きで決まる）。
- ライトは無視する。DupliX はライトなしで描き、レイヤーの「ライトを受ける」がオンなら、状態の欄で「オフにしてください」と案内する（オンのままだと AE のライトが平らな板として当たる）。
- DupliX より後ろのエフェクトは、全コピーを描いた 1 枚の絵に掛かる（通常モードではコピー 1 枚ずつ）。前のエフェクトはコピー 1 枚ずつ（入力の絵に焼き込まれている）。

**仕組み**（12.10 の実験で置き方は確認済み）
1. パラメータの末尾に「高速モード」（チェック、既定オフ）を足す（ストリーム番号とディスク ID を動かさない）。
2. 前処理: カメラ・レイヤー→ワールド・コンプの大きさ・縮小表示を読み、面の M4 を求めて登録する。出力の全体（`max_result_rect`）は画面の大きさ（縮小表示を反映）、結果は要求との共通部分。カメラの行列・レイヤーの行列・コンプの大きさ・時間・縮小表示・パラメータを `GuidMixInPtr` に混ぜる。
3. 描画: 全コピーを、遠いものから順に、正しい遠近で画面の大きさの絵に描く（バイリニア補間、プリマルチプライの "over" 合成、コピーごとの不透明度）。**最初は CPU（複数スレッド）で作る**（ライトなしのバイリニアだけなので、AE のクラシック 3D より軽い見込み）。GPU（CUDA）は、カーネルのコンパイルに CUDA Toolkit が要る（この PC には NVRTC もない）ので、導入を利用者が判断してから別の計画で足す。計画: `docs/superpowers/plans/2026-11-24-fast-mode.md`。
4. フック: コピー数は 1、コピーの一覧は M4 の面 1 枚、不透明度はそのまま。
5. GPU が使えないとき（ソフトウェアのみの設定など）は、CPU で同じ描画をする（遅いことを説明に書く）。

**高速モードで失われるもの**（パラメータの説明に書く）: ほかのレイヤーとの交差と細かい前後（面 1 枚の奥行きで決まる）、ライトと影、被写界深度、コピーのモーションブラー、コピー同士の交差（遠い順に描くだけ）、AE と同じ補間の画質（画素単位の一致はしない）。

**確かめること**: 置き方（模様の試験、縮小表示を含む）、カメラが動いたときにキャッシュが古い絵を返さないこと、通常モードとの見た目の近さ（目視用の比較画像）、速さ（`run_user.ps1 -Mfr OFF` と `run_preview.ps1`、コピー 10・100・1000 枚）。

### 12.10 高速モードの実験（11/24、12.7 の (4) の土台）

- 仕組み: サブレイヤーを 1 枚にし、エフェクトの出力（画面の大きさの絵）を、カメラ正面を向いた面として画面の画素と 1 対 1 に重ねる。M4 = S·C·W⁻¹（S: 画面の点 (x, y) をカメラ空間の深さ d の点 ((x−幅/2)·d/距離, (y−高さ/2)·d/距離, d) に写す、C: カメラ→ワールド（`AEGP_GetEffectCameraMatrix`）、W: レイヤー→ワールド（`AEGP_GetLayerToWorldXform`）。前処理で求める）。
- **置き方は画素単位で完全に一致**（`tests/ae/spike_screen.jsx`＋`run_spike_screen.ps1`、環境変数 `RANDAMU_SPIKE_SCREEN=1`。カメラの移動と回転、レイヤーの回転・拡大縮小・アンカーのずれ、親付きの 3 ケースで模様と最大差 0）。
- 費用（利用者のシーン、aerender の MFR オフ、120 フレーム）: 通常コピー 10 枚 142 ms／フレーム、本物 10 枚 142 ms、通常コピー 1 枚 67 ms、**画面全体の面 1 枚 58 ms**。面の費用はコピーの数に関係なく一定なので、コピー 10 枚で約 2.4 倍、枚数が多いほど差が開く。ただし DupliX がコピーを描く自前の描画の費用が別に掛かる（GPU で描く前提）。
- 実装で守ること: 前処理で `GuidMixInPtr` を必ず呼ぶ（呼ばないと AE の内部確認で描画が中止される）。前処理の `result_rect` は要求の範囲との共通部分にし、全体は `max_result_rect` に入れる（超えると内部確認で中止）。出力はカメラ・レイヤーの変形・コンプの大きさ・時間・縮小表示に依存するので、それらをキャッシュの鍵に混ぜる。縮小表示（`downsample`）への対応。

### 12.9 クラシック 3D の面の描画を GPU に移す案（11/24 調査、未決）

- クラシック 3D の実体は `Required\Advanced3D.aex`（Artisan「Escher」、635 KB）。面 1 枚を、画面上の 1 行ずつ CPU で描く（`sub_180032FE0` など、画素形式・ライトの扱いごとにひな形から作られた多数の版。1 画素ごとに PF.dll の補間（`PF_SubpixelBicubic8` 等、`sub_1800587D0` で選択）→ ライトと影 → 描画モードと不透明度の表 `PF_Get_Xfer1_Opacity_table*` で描画先に合成）。描画先は CPU の画面。解析は `spike/ida/versions/2025/Advanced3D.aex.i64`、呼び元の一覧 `spike/ida/dump_a3d_sample/`、道具 `spike/ida/ida_imports_xref.py`。
- 計測（利用者のシーン、コピー 10 枚、ビューアー経路）: 最高画質 161 ms、ドラフト画質 55 ms → 時間の約 3 分の 2 が画素ごとの補間。
- 案: 全コピーについて「補間と陰影を済ませた色」を GPU でまとめて計算して 1 回で CPU に戻し、行ごとの描画関数を差し替えて合成だけを CPU で行う。上限は約 3 倍（補間以外の 3 分の 1 は残る）。課題: AE の補間（固定小数点の表）・ライト・影の計算を GPU で同じ結果に再現する必要、行ごとの描画関数の多数の版と、どの面を描いているかの特定、AE の版ごとの解析。
- 比べる案: 12.7（面の数そのものを減らす）。

### 12.7 1 枚の絵として出す高速モードと、群れをまとめる高速化（11/24 利用者の要望）

背景（計測、`tests/ae/run_perf.ps1`）: 200 枚・30 フレーム・CUDA で、DupliX 1.46 秒／フレーム、本物の複製レイヤー 200 枚 1.43 秒／フレーム。フックの処理は全体の 1% 未満で、重さは AE のクラシック 3D がコピーを本物のレイヤーとして描く処理そのもの。

- **(4) 全部を 1 枚の絵として出す高速モード（実装する。利用者の決定）**: 普通の複製プラグインと同じく、全コピーを DupliX が自前で（GPU で）描き、1 枚の絵として出す。ほかのレイヤーとの交差・影・被写界深度は正確でなくなる（12.2 の 7 で許容）。
- **(3) 交差しない群れを 1 枚の絵にまとめる（調査・計測の結果、より良い案なら実装。利用者は魅力的と評価）**: 遠くに限らず、手前でも、条件を満たす群れはまとめる。
  - 毎フレーム、そのフレームのカメラで群れを決め直す。条件: 群れのコピー同士が交差しない。かつ、ほかのもの（レイヤー・ほかの群れ・単独のコピー）は、画面上で重なる範囲で群れの奥行きの幅の内側に入らない（完全に手前か完全に奥）。
  - 群れの絵を、そのフレームのカメラで、正しい遠近と前後の順で自前で描く。カメラ正面を向いた 1 枚の面として、群れの奥行きの範囲の中に、画面上で絵とぴったり重なる大きさで置く（サブレイヤーの矩形・M3 でレイヤーの絵の一部を選べる仕組みを使い、エフェクトの出力に群れの絵を並べて渡す見込み。要調査）。
  - 条件があるので、AE が面 1 枚で前後を判定しても、中身を 1 枚ずつ判定した場合と同じになる。カメラが動けば次のフレームで作り直すので、位置関係は崩れない。
  - 崩れる点: ライトと影（面は 1 枚の板として影を落とす・受ける。陰影は自前で再現が要る → 最初は「ライトの影響を受けるコピーはまとめない」）、被写界深度（群れ全体が同じぼけ）、モーションブラー（群れの中の動きのぶれが出ない）、補間の違いによる縁の 1〜2 段階の差。
  - (4) は (3) の群れがコピー全部の場合として、同じ描画の部品を使う。

### 12.5 描画結果に影響しないコピーだけを省く判定（11/24 利用者の提案）

画面外のコピーを単純に省くと、画面外のコピーの影が急に消えるなど、絵が変わることがある（12.3 の 8）。そこで、**描画結果に影響しないと確実に言えるコピーだけを省く判定**を入れる。判定の計算で、かえってレンダリング時間が伸びないようにする（1 枚あたり、コピーを囲む箱と視野の境界面との比較を数回。1 万枚でも 1 ms 程度の見込みで、3D 描画の時間に比べて無視できる）。

省いてよいのは、次をすべて満たすコピーだけ:
- **画面に写らない**: カメラの視野の外にある。視野は、モーションブラーのシャッターが開いている間の動き（コピーとカメラの両方）の全体と、被写界深度のぼけの半径の分だけ広げて判定する。
- **影が画面に落ちない**: 対象レイヤーの「シャドウを落とす」がオフなら満たす。オンなら、影を落とすライトごとに、ライトからコピーを通って奥へ伸びる範囲がカメラの視野と交わらないこと（スポットライトなら、照らす範囲の外にあるだけでもよい）。
- **画面の外の画素を使う処理に影響しない**: 上にある調整レイヤーのぼかしなどは、画面の少し外の画素も使う。プラグインからは自動で分からないので、「余白（px）」のパラメータで判定の範囲を広げる。

実装の要点: `GetSubLayerRects` で省いたコピーを詰めて返し、何番目のサブレイヤーが元の何番目のコピーかの対応表を持つ（コピーごとの乱数と不透明度は元の番号で求める）。カメラ・ライトの値は描画スレッドで AEGP から読む。

既定値（案、着手時に確認）: **オン**。基準は「省いても絵が変わらない」なので、正解比較の試験で、省かない場合と画素単位で一致することを確かめる（画面の端・影・モーションブラー・被写界深度・調整レイヤーのケースを足す）。一致しないケースが見つかったら、判定を保守的な側に直す。
