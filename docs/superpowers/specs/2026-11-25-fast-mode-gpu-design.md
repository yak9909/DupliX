# 高速モードの GPU 化と全体の軽量化 設計書

- 日付: 2026-11-25
- 状態: 承認済み（2026-11-25）
- 前提: 高速モードは 2D レイヤーの普通のプラグイン（設計書 12.13、計画 `docs/superpowers/plans/2026-11-25-fast-mode-plugin.md`、実装済み）

## 目的

利用者の要望（11/25）: 高速モードは「かなり高速化されたが、GPU での高速化がまだ」。特定の重い場面はなく、**全体的に軽くしたい**。方式は「Furikake の方法でよい。もっと良くできるならそうして」。

## 分かっていること

- 今の高速モードは、全コピーを CPU（複数スレッド）で描く。AE のプロジェクトが GPU（この PC では CUDA）の設定でも、このレイヤーは CPU で描かれ、AE は絵を GPU→CPU→GPU と往復させている。
- 通常モードの GPU の経路（入力をそのまま写す）は実装済み。CUDA は `nvcuda.dll` を実行時に読み込んで使っている（`src/effect/gpu_copy.cpp`）。
- **Furikake は GPU で描いていない**（11/25 調査、`spike/ida/furikake/`）: 取り込みに CUDA・OpenCL・DirectX がなく、描画の部品は `RenderCPU::DrawZBuffer`・`BlendLayer` などの CPU 版だけ。速さは CPU の Z バッファ（画素ごとに一番手前だけを残す）によるとみられる。
- 今の DupliX の CPU 版は、画素ごとに重なる全コピーを奥から順に並べて合成する（斜めの重なりも正しい。11/24 の軌道ヌルの不具合の修正）。

## 方式

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A（採用）** | CUDA で今と同じ描き方（画素ごとの奥行きで並べて合成、バイリニア） | 最も速い。往復がなくなる。見た目は CPU 版と同じ | CUDA 以外の GPU 設定では使えない（CPU 版に切り替え） |
| B | Furikake 型の Z バッファ（CPU） | CPU でも速い | 半透明のコピーが重なる所の見た目が変わる（後ろが透けない） |
| C | DirectX・OpenCL で書く | ほかの GPU でも動く | この PC の AE は CUDA しか選べない。手間が倍 |

利用者は作り方を任せた（「もっと良くできるならそうして」）ので、実装者の判断で A を採る。B は見た目が変わるので使わず、CPU 版は結果を変えない工夫で軽くする。

## 設計

**GPU（CUDA）**
1. 描画の処理（カーネル）を `.cu` で書き、ビルド時に CUDA Toolkit の `nvcc` で PTX にしてプラグインに埋め込む。実行時は CUDA ドライバー API（`cuModuleLoadData`・`cuLaunchKernel`、`nvcuda.dll` から読み込む）で使う。使う側の PC はドライバーだけでよい。PTX は古めの版（v12.2 の Toolkit）で作り、新しいドライバーでも古いドライバーでも動くようにする。モジュールは GPU の文脈ごとに 1 回だけ読み込む。
2. 前処理: 高速モードで、AE の GPU が CUDA のときは `PF_RenderOutputFlag_GPU_RENDER_POSSIBLE` を立てる。
3. GPU の描画（`PF_Cmd_SMART_RENDER_GPU`）: コピーごとの射影（3x3）・不透明度・奥行きの一覧と、画面を小さな区画（16×16 px）に分けて各区画に掛かるコピーの一覧を CPU で作って GPU に送る。カーネルは 1 画素 1 スレッドで、自分の区画のコピーだけを見て、入力を補間し、奥行きで並べて合成する。並べる数には上限（例: 1 画素 64 枚）を設け、超えた分は遠いものから順に先に合成する（その画素だけ近似。説明に書く）。
4. AE の GPU の絵の形式（色の並び、アルファの扱い）は最初の実験で確かめてから合わせる。
5. GPU の結果は CPU 版と画素ごとにほぼ同じ（目安 ±2/255）にする。

**CPU 版（GPU が使えないとき）**
6. まず時間の内訳を測る（AE 全体の時間のうち、DupliX の描画・入力の取り込み・それ以外）。
7. 結果を変えない軽量化を入れる。候補: 区画ごとのコピーの一覧（GPU と共通）、手前から見て不透明になった画素はそれより奥の計算を省く、メモリの使い方。

**確かめること**
- GPU と CPU の絵の差（AE の試験、プロジェクトの GPU 設定を CUDA にして描く）。
- 速さ: 利用者のシーンで、コピー 10・100・1000 枚、ビューアーと書き出し、CPU と GPU。前後の数値を報告する。
- GPU 設定がソフトウェアのみ・OpenCL のときは CPU 版で正しく描かれること。

## 目標・目標外

- 目標: 高速モードを全体的に軽くする。GPU 設定のときは描画を GPU で完結させる。
- 目標外: 通常モードの GPU 化（AE のクラシック 3D の描画は AE の中なので対象外）、OpenCL・DirectX 版、画質の選択（多重サンプリングなど）。
- 失敗とみなすもの: 見た目が CPU 版と変わる、GPU が使えない環境で描かれない・落ちる。

## 実装者に任せること

区画の大きさ、1 画素の上限枚数、CPU 版の軽量化の具体的な手段（測定の結果で選ぶ）。
