# 高速モード（全コピーを 1 枚の絵として出す）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** パラメータ「高速モード」をオンにすると、全コピーを DupliX が自前で 1 枚の絵に描き、その絵をカメラ正面の 1 枚の面として画面に 1 対 1 で重ねて出す。コピー 10 枚で 142 ms → 約 60 ms 以下（利用者のシーン、1 フレーム）。

**Architecture:** AE に依存しない純粋な部分（面の M4、コピーごとの画面→元画像の射影変換、CPU のラスタライザ）を `src/core/` に置き、単体テストで確かめる。エフェクトは前処理で行列を AEGP から読んで面の M4 を登録し、描画でラスタライザを呼ぶ。フックは高速モードのレイヤーに「コピー 1 枚＝その面」と答える。GPU（CUDA）は CUDA Toolkit の導入を利用者が判断したあとの別計画。

**Tech Stack:** C++17、MSVC v143、AE SDK 25.6、`std::thread`（行の帯ごとの並列化）、PowerShell 7、ExtendScript、Python（`spike\.venv`）。

**Spec:** `docs/superpowers/specs/2026-11-24-randamu-sublayer-design.md` の 12.10・12.11・12.12（承認済み）。実験の結果は 12.10、実験コードは `src/hook/screen_plane.*` と `src/effect/randamu.cpp` の `SpikeComputePlane`（このタスク群で製品コードに置き換えて消す）。

## Global Constraints

- 対象は After Effects 2025（25.6）、Windows x64、クラシック 3D のみ（Advanced 3D／Cinema 4D では今どおり何もしない）。
- 新しいパラメータは末尾に足す（`RP_FAST`・`RD_FAST`）。既存のストリーム番号とディスク ID は動かさない。
- 高速モードがオフのとき、見た目と速さは今と変わらない（既存の `run_ref.ps1`・`fx_remove`・`run_ui.ps1` が合格のまま）。
- 前処理では必ず `GuidMixInPtr` を呼ぶ（呼ばないと AE の内部確認で描画が中止される）。`result_rect` は要求の範囲との共通部分、全体は `max_result_rect`（超えると中止される）。
- 面の奥行きはレイヤーのアンカーの奥行き。ライトは使わない（ライトなしで描く）。DupliX より後ろのエフェクトは 1 枚の絵に掛かる。
- 描画は奥のコピーから順、バイリニア補間、プリマルチプライの over 合成、コピーごとの不透明度。画素単位で AE と一致しなくてよい（12.12 の決定）。
- フックの中（BEE の仮想関数）から UI スレッドで AEGP を呼ばない。
- 利用者の aep は直接開かない（`build/` にコピーしてから開く）。
- 利用者への文言は日本語（英語化は改名の作業で別途）。

## Review Focus

1. **カメラやレイヤーが動くアニメーション**: 毎フレーム正しい絵になる（キャッシュが古い絵を返さない） → Task 4 の `fast_anim` ケース。
2. **縮小表示（1/2・1/4）**: 面の大きさと位置が正しい → Task 4 の `fast_half` ケース。
3. **カメラの後ろ側にかかるコピー**: 落ちず、そのコピーは描かれない（近い面より手前を切る） → Task 2 の `raster_behind_camera` テスト。
4. **コピー数 0、高速モードのオン・オフの切り替え、エフェクトの削除**: 0 枚なら何も描かれない、オフに戻せば通常モードの絵 → Task 4 の `fast_toggle`・`fast_count0` ケース。
5. **カメラがないコンプ**: AE の既定のカメラで同じように動く（`AEGP_GetEffectCameraMatrix` が既定のカメラを返す） → Task 4 の `fast_nocam` ケース。

### Task 1: 面とコピーの射影の計算（純粋関数）

**Files:**
- Create: `src/core/fast_plane.h`, `src/core/fast_plane.cpp`
- Test: `tests/unit/unit_tests.cpp`

**Interfaces:**
- Produces:
  - `struct CameraView { double camToWorld[16]; double dist; double compW, compH; };`（行ベクトル、`AEGP_GetEffectCameraMatrix` の値そのまま）
  - `bool PlaneM4(const CameraView& cam, const double layerToWorld[16], double depth, double out[16]);` … レイヤー px (x, y) → 画面 px (x, y) に写る面（12.10 の M4 = S·C·W⁻¹）
  - `double AnchorDepth(const CameraView& cam, const double layerToWorld[16], double ax, double ay);` … アンカーのカメラ空間の z
  - `bool CopyHomography(const CameraView& cam, const double layerToWorld[16], const double copyM4[16], double screenToSrc[9]);` … 画面 px → 元画像 px の 3x3（行ベクトル、同次座標）。z が 1 以下（カメラの後ろ側）にかかるコピーは false
  - `double CopyDepth(const CameraView& cam, const double layerToWorld[16], const double copyM4[16], double cx, double cy);` … コピーの中心のカメラ空間の z（描く順番に使う）

- [ ] **Step 1: 失敗するテストを書く** — `fast_plane_maps_pixels_1to1`（任意のカメラ・レイヤー行列で、レイヤー px (x, y, 0) に PlaneM4 と layerToWorld とカメラの投影を掛けると画面 px (x, y) に戻る。誤差 1e-6）、`fast_plane_depth_is_anchor`（PlaneM4 の面上の点のカメラ空間 z が AnchorDepth と等しい）、`copy_homography_identity`（copyM4 = 単位行列・PlaneM4 と同じ配置のとき、screenToSrc が画面 px → レイヤー px の写像と一致）、`copy_homography_behind_camera`（コピーの角の 1 つが z < 1 なら false）。カメラは 12.10 の `cam_moved` 相当（位置 (700,300,−1500)、目標 (1100,600,200)）と既定のカメラの 2 通り。
- [ ] **Step 2: 失敗を確認** — `pwsh tools/build.ps1; build/unit/unit_tests.exe` → 新しいテストが未定義でビルド失敗。
- [ ] **Step 3: 実装** — 投影は 12.10 の事実（画面 px = カメラ空間 xy × dist / z + 幅・高さ/2）。CopyHomography は、レイヤー px → 画面 px の射影（copyM4·layerToWorld·C⁻¹ の後の透視）を z=0 の平面について 3x3 にまとめ、その逆行列。`randamu.cpp` の `Invert4`・`Mul4` はここへ移す。
- [ ] **Step 4: 合格を確認** — `build/unit/unit_tests.exe` → `ALL PASS`。
- [ ] **Step 5: Commit** — `git commit -m "feat(core): fast mode plane and per-copy projections"`

### Task 2: CPU のラスタライザ

**Files:**
- Create: `src/core/raster.h`, `src/core/raster.cpp`
- Test: `tests/unit/unit_tests.cpp`

**Interfaces:**
- Consumes: Task 1 の `screenToSrc[9]`。
- Produces:
  - `struct RasterImage { void* data; int width, height; long rowBytes; int bpc; /* 8, 16, 32 */ int originX, originY; };`（ARGB、プリマルチプライ。AE の PF_Pixel8/16/PixelFloat と同じ並び）
  - `struct RasterCopy { double screenToSrc[9]; double opacity; double depth; };`
  - `void RasterizeCopies(const RasterImage& src, RasterCopy* copies, int n, double dsX, double dsY, RasterImage& dst, int threads);` … dst を透明で埋め、copies を depth の大きい順（奥から）に並べ替えて、各コピーを over で描く。dst の画素 (x, y) は画面 px ((x + originX) / dsX, (y + originY) / dsY) の中心。各コピーは、画面上の外接矩形の内側だけを回る。threads 本で dst の行の帯を分ける。

- [ ] **Step 1: 失敗するテストを書く** — `raster_identity_copies_source`（screenToSrc = 単位行列、不透明度 1 → 8 bpc で dst が src と完全一致）、`raster_opacity_half`（不透明度 0.5 → 各チャンネルが src の半分 ±1）、`raster_back_to_front`（重なる 2 枚、depth の小さい方が上に見える）、`raster_downsample_half`（dsX = dsY = 0.5 → dst の (x, y) が src の (2x+0.5, 2y+0.5) のバイリニア値）、`raster_threads_same_result`（threads=1 と 8 で完全一致）、`raster_behind_camera`（Task 1 で false になったコピーを渡さない側の責任とし、ここでは n=0 で dst が全面透明）。16・32 bpc の版も identity で 1 本ずつ。
- [ ] **Step 2: 失敗を確認** — ビルド失敗。
- [ ] **Step 3: 実装** — 行の帯は `std::thread`。サンプルは src の範囲外を透明として扱う。8/16 bpc は整数の丸め（+0.5）、32 bpc は float。
- [ ] **Step 4: 合格を確認** — `ALL PASS`。速さの目安を単体テストの出力に 1 行出す（1920×1080 に 577×680 を 10 枚、threads = ハードウェアのスレッド数、ms）。
- [ ] **Step 5: Commit** — `git commit -m "feat(core): CPU rasterizer for the fast mode"`

- [ ] **Step 1: パラメータを足す** — チェック「高速モード」（既定オフ、`RD_FAST`）。`PF_ADD_CHECKBOXX(UiName("高速モード", "Fast Mode"), FALSE, 0, RD_FAST)`。
- [ ] **Step 2: 前処理** — 高速モードのとき: AEGP でカメラ（`AEGP_GetEffectCameraMatrix`、コンプ時刻は `AEGP_ConvertEffectToCompTime`）、レイヤー→ワールド（`AEGP_GetLayerToWorldXform`）、コンプの大きさ、アンカーを読み、`PlaneM4(..., AnchorDepth(...))` を `FastSetPlane` に登録。`max_result_rect` = (0, 0, コンプの幅 × dsX, 高さ × dsY)、`result_rect` = 要求との共通部分。`GuidMixInPtr` に、ビルド ID・カメラ行列・dist・レイヤー→ワールド・コンプの大きさ・dsX/dsY・時刻・全パラメータの値を混ぜる。GPU の描画は可能にしない（`PF_RenderOutputFlag_GPU_RENDER_POSSIBLE` を立てない）。入力の checkout は今と同じ。
- [ ] **Step 3: 描画** — 高速モードのとき: 入力を `RasterImage`（origin は入力ワールドの `origin_x/y`）、出力を `RasterImage` にし、`ComputeCopy` の各コピーについて `CopyHomography` が true のものだけ `RasterCopy`（不透明度 = コピーの不透明度、depth = `CopyDepth`）にして `RasterizeCopies`（threads = `std::thread::hardware_concurrency()`）。
- [ ] **Step 4: フック** — 高速モードのレイヤーでは、Count（キャッシュありの問い合わせ）= 1、Rects = 元の矩形・M3 単位行列・M4 = `FastGetPlane`（見つからなければ元の関数を呼ぶ）、不透明度のフックは元の値のまま。
- [ ] **Step 5: ライトの案内** — `AEGP_LayerStream_ACCEPTS_LIGHTS`（`AEGP_GetNewLayerStream`）がオンで高速モードなら `SelfState::FastLights`。
- [ ] **Step 6: ビルドと既存の試験** — `pwsh tools/build.ps1; build/unit/unit_tests.exe; pwsh tests/ae/run_ref.ps1; pwsh tests/ae/run_ui.ps1` → `ALL PASS`、`REF ALL PASS`、`UI ALL PASS`（高速モードはオフなので変わらない）。`run_jsx.ps1 -Jsx tests/ae/fx_remove.jsx ... -Check tests/ae/check_fx_remove.py` → `FX REMOVE ALL PASS`。

### Task 4: AE での確認（置き方・通常モードとの近さ・動き・縮小表示・速さ）

**Files:**
- Create: `tests/ae/fast_mode.jsx`, `tests/ae/check_fast_mode.py`, `tests/ae/run_fast_mode.ps1`
- Modify: `docs/randamu-quickstart.md`（高速モードの説明と、失われるもの）

`fast_mode.jsx` はケースごとに `fm_<case>`（高速モード）と `nm_<case>`（同じシーンで通常モード）を作り、レンダーキューに入れて保存する。`run_fast_mode.ps1` は aerender（MFR オフ・オン）で描き、`check_fast_mode.py` で比べる。

| ケース | 内容 | 合格の条件 |
|---|---|---|
| `fast_identity` | コピー 1 枚・範囲 0、白い平面 | fm と nm の差の最大 ≤ 8、平均 ≤ 0.5（補間の違いだけ） |
| `fast_scatter` | コピー 10 枚、位置・回転・拡大縮小の範囲あり、PNG 素材 | 差の平均 ≤ 2、差 > 32 の画素が全体の 1% 以下（交差しない配置） |
| `fast_anim` | カメラと対象レイヤーにキーフレーム、30 フレーム | 各フレームの fm を、そのフレームだけ単独で描き直した fm と比べて差の最大 ≤ 1（キャッシュが古い絵を返さない） |
| `fast_half` | `fast_scatter` を 1/2 の解像度で | 1/2 の nm と、上の条件で比べる |
| `fast_nocam` | カメラなし | `fast_scatter` と同じ条件 |
| `fast_count0` | コピー 0 枚 | fm が全面透明（背景だけ） |
| `fast_toggle` | 高速モードをオン → オフ（同じ AE のセッション、スクリプトで切り替え） | オフにした後の fm が nm と差の最大 ≤ 1 |
