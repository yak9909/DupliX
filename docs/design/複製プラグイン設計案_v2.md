# 複製プラグイン 設計案 v2（シンプル版）

- 作成日：2026-11-26
- 位置付け：`AE_Procedural_Instance_System_Prototype.md`（ChatGPT 案）を下敷きに、**入口はシンプル・奥は細かく**を優先して組み直した対案
- C++ や SDK に関する記述は構想段階のもの。AE 実機での確認が要る点には「要検証」と書いた

---

## 0. 結論（先に要点）

ChatGPT 案の「格子を一般化して、配置をパラメーター空間 → 実空間の写像として扱う」という骨組みは良いので、そのまま使う。変えるのは次の 3 点。

1. **すべてを「時刻と要素番号だけで決まる関数」にする。**
   履歴に依存するシミュレーション（衝突・相互作用・追尾・イベント・ステートマシン・プロジェクタイル）は、このプラグインでは扱わない。発生・寿命・重力・乱流のように時刻から直接計算できるパーティクル表現は、Emission（4.5 節）として扱う。AE はフレームを順不同で要求し、MFR では複数フレームを同時に計算する。そのため履歴に依存する仕組みは、キャッシュとスレッド安全性の問題をすべて抱え込むことになる。この 1 点を削るだけで、設計の半分近くが消える。
2. **モディファイアは「1 つのドライバーで複数の属性を一度に動かす」形にする**（Cinema 4D MoGraph の Effector ＋ Field 方式）。
   ChatGPT 案では 1 スロットに Generator / Domain / Target / Space / Blend / Falloff / Selection の 7 軸を選ぶ必要があり、Target も 1 つだけだった。そのため「波で位置と大きさを同時に動かす」だけでも 2 スロットが要る。
3. **配置は 4 種類 × サンプリング 2 種類だけにする。** 円形・多角形・放射状・螺旋・同心円・円筒は、すべて Polar 1 つのパラメーター違いで作る。ランダム配置は独立したモードにせず、**どの配置にも使える「Scatter」サンプリング**にする。

## 1. 全体の構造

```
Count（A × B × C）
   │  要素番号 i → 整数座標 (a,b,c) → 正規化座標 (u,v,w)
   ▼
Shape（配置）……… Grid / Polar / Sphere / Path、サンプリングは Regular / Scatter
   │  各要素に「位置」と「向き（T, N, B）」を持たせる
   ▼
Flow（流れ）……… u / v / w をずらしてループさせる（経路に沿った移動）
   ▼
Emission（任意）… 生まれる時刻・Age・初速・重力・乱流（Shape を発生源として使う）
   ▼
Morph ……………… Shape B へ補間（同じ要素番号どうし）
   ▼
Modifier × 6 ……… ドライバー → マスク → 各属性への量
   ▼
Sources / Render … 複製元・時間・ビルボード・Global Transform
```

ChatGPT 案との違い：Sampler / Mapping / Frame という 3 つの概念は、**ユーザーには見せずに内部の実装にとどめる**。ユーザーに見えるのは「Shape」という 1 つの概念だけにする。

### 1.1 Count は Shape から切り離す

個数（A × B × C）は Shape の外に置く。Shape は、その個数を**どう解釈するか**だけを決める。こうしておくと、Shape A と Shape B で要素番号が必ず一対一に対応するので、Morph に対応付けの処理が要らなくなる。

### 1.2 向き（Frame）だけを持たせ、中心点は持たせない

構想にある「中心点と言ったけど方向だけでいいかもしれない」に賛成する。各 Shape は要素ごとに次の 3 軸を返す。

| 軸 | 意味 | Grid | Polar | Sphere | Path |
|---|---|---|---|---|---|
| **T**（Along） | A 方向に進む向き | +X | 円周の接線 | 経線の接線 | パスの接線 |
| **N**（Out） | 外向き | +Z（面の法線） | 中心から外 | 表面の法線 | パスの法線 |
| **B**（Side） | 残りの 1 軸 | +Y | 高さ方向 | 緯線の接線 | 従法線 |

「中心を基準にした拡大」は「N 方向への移動」で表せる。そのため、中心点を参照する仕組みは要らない。中心・極・長さ 0 のパスなどで向きが決まらない場合は、ひとつ前の要素の向きを使う。

## 2. Shape（配置）

| Shape | A | B | C | 主なパラメーター |
|---|---|---|---|---|
| **Grid** | X | Y | Z | Size XYZ、Brick（行ごとのずらし） |
| **Polar** | 角度 | 半径 | 高さ | Inner / Outer Radius、Angle Range、**Sides**（0 なら円、3 以上なら多角形）、**Twist**、Height |
| **Sphere** | 経度 | 緯度 | 殻（層） | Radius、Shell Spacing、Latitude Range |
| **Path** | 進行度 | 列（横方向） | 列（奥行き） | Mask、Row Spacing、Closed 判定、Arc-length（等間隔化） |

構想にある配置は、次のように Polar 1 つでまかなえる。

| 構想 | 設定 |
|---|---|
| 円形 | A = 24、B = 1 |
| 多角形 | 上の設定に Sides = 5 を足す |
| 放射状 | A = 本数、B = 1 本あたりの点の数 |
| 螺旋 | 放射状に Twist を足す（A が「線の本数」を兼ねる。構想の指摘どおり） |
| 多重リング・同心円 | B = 層数 |
| 円筒 | C = 段数、Height を指定 |

### 2.1 Scatter サンプリング（ランダム配置）

`Sampling: Regular / Scatter` の切り替えを、すべての Shape に共通で持たせる。Scatter にすると、(u,v,w) を格子からではなく**低食い違い列**（R2 列や Sobol 列）から取る。

- 同じ場所に集まりにくい（構想の要求）。そのうえ Poisson Disk と違って計算が O(1) で済み、結果も決定的になる。
- **Count を増やしても、既存の要素の位置が変わらない。** 列の先頭から順に使うため。アニメーションで個数を変える用途で効く。
- Shape ごとに面積の補正をする（Polar の半径は √v にする、Sphere は等面積にする、など）。
- 「Grid で Scatter」は箱の中に散布、「Polar で Scatter」は円盤の中、「Sphere で Scatter」は球面上、「Path で Scatter」はパス上にばらまく、という使い方になる。
- 格子の構造を少しだけ崩したいときは、Scatter ではなく Modifier の Random（Position）を使う。

### 2.2 多面体

最初の版には入れない。後の段階で Sphere の追加オプション（Platonic：正多面体の頂点・辺・面に配置）として足す。Sphere の A × B 構造に収まらないため、Scatter と同じく「要素番号の順に点を並べるだけ」の配置として扱う。

## 3. Flow（範囲内のループ・経路に沿った移動）

Flow は (u,v,w) そのものをずらす。実空間で動かすのではなく、パラメーター空間で動かす。そのため、どの Shape でも同じパラメーターで次の動きが得られる。

| | Grid | Polar | Sphere | Path |
|---|---|---|---|---|
| Offset A | 横にスクロール | **公転** | 自転 | **パスに沿って移動** |
| Offset B | 縦にスクロール | **リングが外へ流れる** | 緯度方向に流れる | 列の入れ替え |

パラメーターは軸ごとに次のとおり。

- **Offset**（主となるパラメーター。キーフレームを打つのはこちら）
- **Speed**（Offset に Speed × 時間 を足す補助。キーフレームは打たない前提。速度にキーを打つと移動量が不連続になる問題を、この役割分担で避ける）
- **Speed Variance**（要素ごとの速度のばらつき。乱数は要素番号から決まる定数なので、時間の関数のまま保てる）
- **Step**（離散移動。0 なら連続、1 なら 1 コマずつ飛ぶ）
- **Boundary**：Wrap / Ping Pong / Clamp
- **Edge Fade**：Wrap の継ぎ目で縮小・フェードする幅（開いたパスや Grid の端で、急に現れたり消えたりするのを隠す）

## 4. Morph（配置の切り替え）

- `Shape B` を 1 つだけ持つ（Shape B 用の Count は持たない）。`Morph` が 0〜100 % のとき、位置と向きを補間する。向きの補間には slerp を使う。
- 対応は**要素番号どうし**の一通りだけにする。Scatter の要素番号は列の順番なので、Grid ⇄ Scatter の Morph も「格子の i 番目が散布の i 番目に飛ぶ」ことになる。こう決めておけば対応のずれは起きない。
- Morph の量は Modifier から要素ごとにずらせる（下の Stagger を参照）。これで「左から順に変形する」「ランダムな順で変形する」が作れる。
- 3 つ以上の配置をつなぎたいときは、エフェクトを 2 つ重ねるのではなく、Shape B の設定にキーフレームを打つ。Shape の種類は途中の値を取れないので、切り替えるのは Morph が 0 % か 100 % のときにするよう案内する。

## 4.5 Emission（時間で決まるパーティクル）

Emission を有効にすると、各要素は「生まれる時刻」と「経過時間（Age）」を持ち、Shape は**発生源**（どこから・どの向きに出すか）として使われる。すべて時刻と要素番号から直接計算でき、前のフレームの結果は使わない。

### 4.5.1 発生

| パラメーター | 意味 |
|---|---|
| Start / Duration | 発生を始める時刻と、発生させる長さ（「n 秒地点から n 秒間」） |
| Rate | 毎秒の発生数（キーフレーム可） |
| Birth Jitter | 生まれる時刻の乱れ |
| Life / Life Random | 寿命とそのばらつき |
| Loop | 寿命が尽きた要素を次の周期で生まれ直させる（少ない Count で発生し続ける） |
| Time | Normal / Hold（指定した時刻の状態で止める。「n 秒地点の状態を配置にする」） |

- 要素の総数は Count（A × B × C）。i 番目の要素が生まれる時刻は、Rate を時間で積み上げた表から逆に引く。Rate にキーフレームを打っても、前のフレームの結果は要らない。
- Age が 0 未満、または Life 以上の要素は描かない。
- Shape の位置・向き・初速・大きさ・色などは、**生まれた時刻の値**を読む。発生源をキーフレームで動かすと、軌跡が残る。

### 4.5.2 運動

```
位置 = 発生位置(b) + 初速方向(b) × 初速(b) × Age     ← 生まれた時刻 b の値
     + 力の項（重力・風）                              ← 積み上げた表の差
     + 乱流の項                                         ← 下記
```

- **初速**：Speed、Speed Random、方向（N 軸 / T 軸 / 指定方向）、Spread（円錐状の広がり）。
- **重力・風**（画面全体で同じ向きの力。キーフレーム可）：力を 0 秒から時間で 2 回積み上げた表 G1・G2 を作り、`G2(t) − G2(b) − G1(b) × Age` を足す。表は全要素で共有し、パラメーターだけで決まる。
- **Drag**（空気抵抗）：一定値なら式で計算できる（キーフレームを打つ場合は表に含める）。

### 4.5.3 乱流

乱流は、位置に足す「変位」として計算する。力として 1 ステップずつ積み上げることはしない。見た目はシミュレーションの乱流に近く、どの時刻でも直接計算できる。

```
乱流の項 = Amount × Ramp(Age) × CurlNoise( 基準位置 × Scale, Evolution + Age × Flow Speed )
```

- **Curl Noise** を使う。発散のないノイズなので、湧き出しや吸い込みのない「流れている」見た目になる。
- **基準位置**は、乱流を足す前の位置（発生位置＋初速＋力）。粒は移動先のノイズを拾うので、渦に巻かれて流れていくように見える。
- **Ramp(Age)**：生まれた瞬間は 0 で、Age とともに強くなる（発生源から離れるほど乱れる）。Ramp の長さはパラメーターで決める。
- パラメーター：Amount、Scale、Complexity（オクターブ数）、Evolution、Flow Speed、Ramp。すべてキーフレーム可。
  - Amount と Scale のキーフレームは、評価している時刻の値を使う（生まれた時刻の値ではない）。キーを打つと全体の乱れ方がそのまま変わる、という分かりやすさを優先する。
- 本物の乱流（速度場に沿って 1 ステップずつ流す）との違い：粒どうしの流れが交差しても破綻しないが、長い寿命で強い乱流をかけると「流された先の場」を正確には反映しない。見た目の差が問題になる用途は、パーティクルプラグインに任せる。

### 4.5.4 既存の仕組みとのつながり

- **Morph**：Shape B に「Emission の結果」を選べる。「飛び散った n 秒後の形から格子へ集まる」「格子が崩れて飛び散る」などに使う。
- **Modifier**：Wave / Stagger の Along・Order に **Age**（正規化した Age も）を加える。Mask に **Age Range** を加える。これで「生まれてから縮む」「最後の 20 % でフェード」などが作れる。
- **Sources**：Time Offset の基準に「生まれた時刻」を選べる（動画素材を、生まれた瞬間から再生する）。

### 4.5.5 Emission で扱わないもの

衝突・跳ね返り、要素どうしの相互作用、引力点（位置で強さが変わる力）、追尾、途中の出来事による別の発生。これらは粒自身の位置に応じて動きが変わるため、1 ステップずつ進めるシミュレーションが要る。パーティクルプラグインで扱う。

## 5. Modifier（いちばん大事なところ）

**1 スロット = ドライバー 1 つ → マスク → 属性ごとの量（複数を同時に）**

```
Modifier 1
├ Type        : Wave / Noise / Random / Stagger / Map / Constant
├ ドライバーの設定（Type によって表示が変わる）
│   Wave   : Along（A / B / C / Index / Distance / X / Y / Z / Age）、Frequency、Phase、Speed
│   Noise  : Scale、Evolution、Speed（実空間の位置で評価）
│   Random : Seed（要素番号から）
│   Stagger: Progress、Order（Index / A / B / Random / Distance / Age）、Softness
│   Map    : Layer、Sample At（UV / Screen）、Channel
├ Mask        : All / Index Range / Every N / Group（行・リング）/ Field / Age Range
│   Index 範囲・N 個おき・Field（中心と半径と柔らかさ）
├ 量（0 のものは計算しない）
│   Position T / N / B（向きの軸に沿って）
│   Shift A / B（パラメーター空間でずらす = 経路に沿って移動）
│   Rotation、Scale、Opacity、Color（Tint）、Time Offset、Source Shift、Morph
└ Strength
```

### 5.1 ChatGPT 案から簡素にした点

| ChatGPT 案 | この案 | 理由 |
|---|---|---|
| Generator と Domain を別々に選ぶ | Type と、その中の Along の 1 つ | ほとんどの組み合わせは意味が決まっている。Noise の入力は実空間の位置、Random の入力は要素番号、で固定してよい |
| Target を 1 つ選ぶ | **すべての属性に量を持たせる** | 1 つの波で位置と大きさを同時に動かせる。0 の属性は計算を飛ばす |
| Space（5 種類） | Position T/N/B と Shift A/B の 2 系統だけ | 「向きの軸に沿って動かす」と「経路に沿って移動する」の区別は、属性の名前で示せる |
| Blend（Add / Multiply / Replace…） | 固定（位置・回転は加算、大きさ・不透明度は乗算） | 選べる意味がほとんどない |
| Selection と Falloff が別の概念 | Mask の 1 つにまとめる | |
| モディファイアの順序を自由に並べる | 上から順に足していく。Shift と Morph だけは先に処理する | 処理の段階はプラグインが決め、ユーザーには並べ替えさせない |

### 5.2 指定レイヤーのトランスフォームで影響を与える（Cavalry 風）

これは Mask の `Field` で扱う。Field は「中心・半径・柔らかさ」で範囲を決める球（2D では円）で、ヌルレイヤーを動かすと、その周りの複製物だけが変化する。中心と半径をレイヤーから受け取る方法は 2 通りあり、P0 で比較する。

- **案 A**：レイヤーパラメーターで指定したレイヤーの変換行列を、AEGP で読む。手軽だが、そのレイヤーを動かしてもエフェクトが再計算されないおそれがある（ChatGPT 案の R27）。**要検証。**
- **案 B**：3D Point と Size をパラメーターとして公開し、ユーザーにエクスプレッションのピックウィップでヌルにつないでもらう。AE がつながりを把握しているのでキャッシュは確実に効くが、つなぐ手間がかかる。

案 A が安定して動けば、案 A を表に出し、案 B は「自分でつなぎたい人向け」に残す。

Map（レイヤーの明るさで制御）も同じ考え方で、どのレイヤーのどの時刻を参照するかは、AE のレイヤーパラメーターの仕組みに任せる。

## 6. Sources（複製元）・時間・描画

- **複製元**：レイヤーパラメーターを固定で 8 個まで持つ（パラメーターの数は PARAMS_SETUP の時点で決まり、後から増やせない）。
  - 割り当て：Sequential / Random / By A / By B（行ごと、リングごと）
  - Modifier の `Source Shift` で番号をずらす。**指定した要素番号の複製元だけを変える**には、Mask を Index Range にして Source Shift を 1 にする。
- **時間**：Time Offset（Modifier で要素ごとにずらせる）、Time Mode（Normal / Hold / Loop）、**Quantize**（素材を取ってくる時刻を N フレーム単位にそろえ、取得回数を減らす）。
  - 同じ（複製元, 時刻）の素材は 1 回だけ取得して使い回す。
- **ランダムに登場**：専用の機能は作らない。Modifier を `Stagger`（Order = Random）にして Scale と Opacity に量を与える。Progress にキーフレームを打てば、ランダムな順に登場する。
- **描画（3D が前提）**：内部は最初から 3D で計算し、AE のカメラ（位置・向き・画角・被写界深度）に連動させる。2D は「カメラなし・Z = 0」の特殊な場合として扱う。
  - Billboard（カメラ正対 / 向きの軸に沿う / オフ）
  - 奥行きによる並べ替え（要素番号や乱数は並べ替えの影響を受けない）
  - Global Transform（全体の位置・回転・大きさ）
  - 遠近による大きさの変化、奥行きでのフェード（Depth Fade）
  - AE の 3D レイヤーと前後関係を正しく重ね合わせることはしない（エフェクトは自分のレイヤーの中に描くだけなので）。

## 7. Effect Controls の構成

```
Duplicator
├ Count A / B / C ………………… 3
├ Shape ……………………………… Type, Sampling, Seed, 各 Shape の設定（表示を切り替え）約 12
├ Flow（ツイルを閉じた状態）… Offset / Speed / Var / Step × A・B、Boundary, Edge Fade 約 10
├ Morph（同）……………………… Enable, Amount, Shape B の設定 約 12
├ Modifier 1〜16（同）………… 1 スロット約 25 × 16 = 400（使っているものだけ表示）
├ Sources ………………………… Layer 1〜8, Assign, Time Mode, Quantize 約 12
├ Render …………………………… Billboard, Sort, Camera, Depth Fade, Global Transform 約 12
└ 合計 約 460（最初に表示されるのは約 20）
```

- **何も触らなくても絵が出る**こと：エフェクトを適用すると、自分のレイヤーを素材にした 5 × 5 の Grid が表示される。
- Type や Enable に応じて関係のないパラメーターを非表示にする。ただし、Effect Controls で非表示にしたパラメーターがタイムライン上でも隠れるかどうかは**要検証**。
- スロットの数は、後から増やすと既存のプロジェクトとの互換性の扱いが面倒になる。最初に多めに確保しておく（7.1 節）。

### 7.1 モディファイアを動的に追加・削除する（Custom UI）

AE のパラメーターは PARAMS_SETUP の時点で数が決まり、後から増やせない。そのため「本当に増やす」ことはできず、次の 2 通りのどちらかになる。

| | 案 1：見かけ上の動的追加（推奨） | 案 2：スタック全体を独自データにする |
|---|---|---|
| 仕組み | 実パラメーターのスロットを多め（例：16 個）に確保して隠しておき、Custom UI の「＋」ボタンで次のスロットを表示する | モディファイアの一覧を Arbitrary Data パラメーター 1 個に詰め、Custom UI で全部描く |
| キーフレーム | 各パラメーターに普通に打てる | 一覧全体で 1 本のキーになる。個別の値に打てない |
| エクスプレッション | つなげる | つなげない |
| 個数の上限 | 確保した数まで | 実質なし |
| 実装の重さ | 中 | 大（UI・Undo・保存形式をすべて自前で作る） |

**案 1 に決定（2026-11-26）。** 個別の値にキーフレームやエクスプレッションを使えなくなるのは致命的なので、案 2 は採用しない。今後、Custom UI まわりの設計では「すべての値が AE の実パラメーターとして存在し、キーフレーム・エクスプレッション・ピックウィップが使える」ことを崩さない。Arbitrary Data に持たせてよいのは、表示順の対応表のように、キーフレームを打つ対象にならない補助的な情報だけとする。

案 1 の要点：

- **並べ替えはパラメーターを動かさずに行う。** 「表示の順番 → スロット番号」の対応表を小さな Arbitrary Data に持たせ、並べ替えではこの表だけを書き換える。こうするとキーフレームはスロットと一緒に残る。
- **削除**は、スロットを無効にして隠し、値を初期値に戻して空きスロットとして再利用する。
- **複製**は、スロットの値（キーフレームを含む）を空きスロットに写す。キーフレームの写し方は AEGP の Keyframe Suite を使う想定（要検証）。
- **折りたたみ**：使っているスロットだけを表示する。Effect Controls では PF_PUI_INVISIBLE、タイムラインでは AEGP_SetDynamicStreamFlag（HIDDEN）で隠す想定。SDK の Supervisor サンプルが同じ手法を使っている（実際の挙動は要検証）。
- 上限は 16 スロットを目安にする。1 スロット約 25 パラメーターなので、全体で約 500 パラメーターになる。パラメーターが多すぎると AE の UI が重くなるおそれがあるため、上限は P0 で実測して決める。

Custom UI を作るまでの間は、固定 6 スロットとして普通に使える。Custom UI は後から足せる設計にしておく（パラメーターの並びは最初から 16 スロット分を確保しておく）。

## 8. 作例：手数で比べる

| 作りたいもの | 操作 | 触るパラメーター数 |
|---|---|---|
| 螺旋 | Shape = Polar、A = 7、B = 9、Twist = 240° | 4 |
| 同心円縞 | Polar、B = 12 ／ Modifier 1：Wave、Along = B、Scale と Opacity に量 | 5 |
| リングが外へ流れてループ | Polar、B = 6 ／ Flow：Speed B = 0.2、Edge Fade = 10 % | 4 |
| パスに沿って 1 コマずつ移動 | Shape = Path（マスク）／ Flow：Speed A、Step = 1 | 3 |
| 8 番から 12 番だけ素材を変える | Modifier：Constant、Mask = Index 8–12、Source Shift = 1 | 4 |
| 格子から球へ、左から順に変形 | Morph：Shape B = Sphere ／ Modifier：Stagger、Order = A、Morph = 100 % | 5 |
| ヌルの周りだけ膨らむ | Modifier：Constant、Mask = Field（ヌル）、Scale と Position N に量 | 4 |

ChatGPT 案のスロット方式では、たとえば同心円縞（Scale と Opacity の両方）を作るのに、Generator / Domain / Target / Space / Blend をそろえたスロットが 2 つ要る。

## 9. 削ったもの・後回しにしたもの

| 項目 | 扱い | 理由と代わりの方法 |
|---|---|---|
| 発生・寿命・重力・風・乱流 | **このプラグインの Emission（決定）** | 時刻から直接計算できる範囲に限る（4.5 節）。キーフレームは、生まれた時刻の値を読むか、時間で積み上げた表で扱う |
| 衝突・相互作用・引力点 | **別プラグイン（決定）** | 粒自身の位置で動きが変わるため、履歴に依存する。AE の順不同評価や MFR と相性が悪い |
| イベント（ECA）/ ステートマシン | 別プラグイン | 同上 |
| プロジェクタイル（追尾・着弾） | 別プラグイン（決定） | ただし「時刻を指定して到達する」ところまでなら、この案でも作れる：Path（発射地点 → 目標）＋ Flow の Offset にキーフレーム、着弾点に置いたもう 1 つの Duplicator で Stagger の Progress を着弾の時刻から 0 → 100 %。追尾は、パスの終点をヌルにつなげば見た目上は再現できる（要検証） |
| 履歴依存のシミュレーション・チェックポイント | 扱わない | 時間の関数だけにすることがこの案の前提 |
| Nested Distribution（配置の入れ子） | 後回し | 個数が掛け算で増え、UI も入れ子になる。エフェクトを 2 つ重ねる（1 つ目の出力を 2 つ目の素材にする）ことで代用できる |
| 多面体 | 後回し（2.2 節） | |
| Poisson Disk | 入れない | Scatter（低食い違い列）で目的は果たせる |
| 最適な対応付けの Morph、個数の異なる Morph | 入れない | Count を共通にしたので不要 |
| ノードエディター / DSL / System Designer | 入れない | |

## 10. 構想の各項目の行き先

| 構想 | この案での実現方法 |
|---|---|
| 格子状（GetColor-V2R・Form 風） | Shape = Grid |
| ランダム（集中しない仕組み） | Sampling = Scatter（低食い違い列）。小さな揺らぎなら Modifier の Random |
| 円形・多角形・層・同心円縞 | Polar（Sides、B = 層数）＋ Wave（Along B） |
| 球状 | Shape = Sphere（C = 殻の層） |
| 多面体状 | 後回し（Sphere の Platonic） |
| 中心を基準にするモディファイア | 向きの N 軸（外向き）に沿った Position / Scale |
| リングが移動してループ | Flow Offset B ＋ Wrap ＋ Edge Fade |
| 一列・複数列 | Path（B = 列）、Grid（A だけ） |
| 接線方向のモディファイア | Position T、または Shift A（経路に沿った移動） |
| パスに沿って移動（連続・離散） | Flow Offset A ＋ Step |
| 放射状 → 螺旋（線の本数を兼ねる） | Polar の A = 本数 ＋ Twist |
| 回転移動・速度のばらつき | Flow の Speed A ＋ Speed Variance |
| 複数の複製元 | Sources（最大 8） |
| ビルボード化 | Render の Billboard |
| 指定の範囲内をループ | Flow の Boundary（Wrap / Ping Pong）＋ Edge Fade |
| ランダムに登場 | Stagger（Order = Random）→ Scale / Opacity |
| タイムサンプリング | Time Offset（Modifier）＋ Time Mode ＋ Quantize |
| 指定した要素番号をいじる | Mask = Index Range / Every N |
| 指定レイヤーのトランスフォームで影響（Cavalry 風） | Mask = Field（ヌルにつなぐ。案 A / B は P0 で比較） |
| 正弦波・ノイズ・マップ参照 | Modifier の Wave / Noise / Map |
| 配置モード間のスムーズな遷移 | Morph（同じ要素番号どうし）＋ Stagger で順番にずらす |
| 格子の拡張ですべて作れる | Count A × B × C を共通にし、Shape がそれを解釈する、という形で採用 |

## 11. 実装の順番

| 段階 | 内容 | 終わりの条件 |
|---|---|---|
| P0 | SDK の検証：複数レイヤー × 複数時刻の取得、自分のマスクのパス、カメラの取得、MFR、Field の案 A / B、パラメーターの非表示（Effect Controls とタイムライン）、約 500 パラメーターでの UI の重さ、過去の時刻のパラメーターを大量に読む負荷、途中のキーフレームを変えたときに後ろのフレームが描き直されるか | 順不同のレンダリングで結果が一致する |
| P1 | Count、Grid、Polar、**3D 描画とカメラ連動**、Billboard、奥行きの並べ替え、Seed | 作例の「螺旋」をカメラで回り込んで見られる |
| P2 | Modifier（Wave / Noise / Random / Constant）、Mask（Index）、固定 6 スロット表示 | 「同心円縞」「指定番号だけ変える」が作れる |
| P3 | Flow、Path | 「リングがループ」「パスに沿って移動」が作れる |
| P4 | Sources（複数・時間・Quantize）、Stagger | 「ランダムに登場」が作れる |
| P5 | Sphere、Scatter、Morph | 「格子から球へ順に変形」が作れる |
| P6 | Field、Map、Depth Fade | 「ヌルの周りだけ膨らむ」が作れる |
| P7 | Emission（発生・寿命・初速・重力と風の表・乱流）、Morph との連携、Age を使う Modifier | 「n 秒地点から n 秒間発生」「Rate にキーフレーム」「n 秒後の形から格子へ集まる」が作れ、ランダムシークでも結果が変わらない |
| P8 | Custom UI（モディファイアの追加・削除・並べ替え・複製、最大 16 スロット） | 並べ替えてもキーフレームが崩れない |
| 後 | 多面体、Nested | |
| 別 | パーティクル・プロジェクタイル用のプラグイン | |
