## 2. 実装で分かったこと（Task 2〜5）

- ワールド変形の回転の順は、コピーと同じ `S·Rz·Ry·Rx`（行ベクトル）で AE のレイヤーの X/Y/Z 回転と一致した（`world_xform.jsx`、差 0）。
- 「ワールドの回転 × レイヤーの不均一な拡大縮小」はせん断になり、ワールド変形では正確に表せない（書き写しは近似）。
- スクリプトで親子付けすると、AE は子のワールドの向きを保つように子の方向を変える。試験では親子付けのあとに方向を 0 に戻す。
- 2D にしたレイヤーの位置・拡大縮小は、スクリプトでは 3 成分のまま読める（z は使われない）。
- 高速モードをオンにした時点の 2D の位置のずれも、書き写しでワールド変形に入る（試験 `fast_move2d` は、オンにしたあとで動かす）。
- 利用者のシーン（`run_as_is.ps1`、`run_orbit_order.ps1 -Deg 26`）は新しい高速モードで合格（高速と通常の差の平均 0.6）。軌道のアニメーションを 120 フレーム比べる試験は、親のアニメーションを写さない決定により前提がなくなった（角度を固定した 1 フレームだけ有効）。

## 4. 実装中の判断と最終レビュー

計画からずらした判断（実装者が決めたもの）:
- ワールド変形の回転の順は計画の書き方（Rx·Ry·Rz）ではなく、コピーと同じ `S·Rz·Ry·Rx`（AE と一致を確認）。
- ワールド変形の位置はレイヤーの座標でのずらしなので、レイヤーの拡大縮小が掛かる。
- `PlaneM4`・`AnchorDepth` は製品では使わなくなったが、`CopyHomography` の単体テストの準備に使うので残した。
- 試験の作りの修正: `fast_move2d` は奥のレイヤーのない双子のコンプと比べ、高速モードをオンにしたあとで動かす。`fast_remove` の比較先は同じ 2D レイヤー。`world_xform` は `saveFrameToPng` で描く。利用者のシーンの前後の絵は `run_as_is` のものを使い、`run_orbit_order` は `-Deg 26` だけ。
- `TransferLayerToWorld` は `params[]` を受け取らず、今のワールド変形を受け取って新しい値を返す（書き込みは呼び出し側）。

最終レビュー（別のレビュー役、Critical なし）で直したもの:
- 位置の次元が分割されていると、途中で失敗してレイヤーが半分だけ初期化されていた → 何も変える前に確かめて止める（`toggle_separated`）。
- ワールド変形にキーフレームがあると、`params[]` への書き込みはその時刻にキーフレームを 1 つ足すだけで、ほかのキーフレームが正しく写らない（AE で確認: 2 個 → 3 個）→ レイヤーが初期状態でないときは止めて「状態」で案内し、初期状態なら何も書かない（`toggle_world_keys`、`toggle_initial_keys`）。
- 途中で一部の設定に失敗したときも、ワールド変形は書く（Partial）。「写せませんでした」の案内が出ていなかったのも直した。
- カメラだけが動く場合にキャッシュが古い絵を返さないか → 試験 `fast_camonly` を足し、問題なし（修正不要）。
- このレイヤーを親にしているほかのレイヤーが一緒に動く件 → 手引きに書いた（自動で補正するには別の実験が要る）。

後回しにした軽微な指摘:
- 高速モードの前処理は毎回パラメータを読み、登録の世代を進める（もともと描画ごとに進めているので影響は小さい）。
- 「状態」の案内の記録（`g_transferNote`）は、エフェクトの削除や取り消しでは消えない。登録が失敗したときに前のレイヤーの鍵に付くことがある。
- 11/24 の高速モードで保存したプロジェクト（高速モードがオンの 3D レイヤー）は、開くと絵がずれて見える（「状態」は 2D にするよう案内する）。
- 取り消しのあと、シーケンスデータの中のワールド変形の写しが古いまま残る（読み込み直後の最初の描画まで）。
- アンカーポイントにアニメーションがあると、書き写しの時刻以外で少しずれる。
- 計画の `max_result_rect` の丸め（計画は ceil、実装は左上を floor）。
